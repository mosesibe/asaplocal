Every email the platform sends is currently an unstyled fragment — a bare <h2> and a raw URL. Below are three complete directions, rendered as real email HTML so what you see is what an inbox gets.

Before you judge them

Email HTML is not web HTML.

These samples deliberately look "old-fashioned" under the hood, because that is the only thing that renders consistently. All three directions are built to the same rules:

  • Tables for layout. Outlook on Windows renders with Word's engine — flexbox and grid simply don't work.
  • Every style inline. Gmail strips much of what lives in a stylesheet.
  • 600px wide, fluid below that. The de-facto standard that survives every client.
  • Padded-anchor buttons. No border-radius reliance; they degrade to a solid rectangle in Outlook rather than breaking.
  • Light-mode only. Dark-mode email support is genuinely inconsistent, so these are designed to hold on a light ground rather than gamble.
Rendering note: the samples below are the actual email markup embedded in this page, on a simulated inbox background. Unlike the rest of this page, they do not follow your light/dark preference — by design.

My recommendation

Pick 01 as the base, borrow 02's data block.

Signal + Docket's detail table

01 Signal should be the house style: the brand band earns recognition across nine different emails from three apps, which matters more than subtlety when a provider is scanning a busy inbox for a lead alert. But 02's labelled data block is genuinely better for the emails that carry facts — lead alerts, booking confirmations, quotes — so I'd bring that panel into the Signal shell as a reusable piece rather than picking one wholesale.

03 Letter is the one I'd still use for two specific emails: passwordReset and verifyEmail. Security mail benefits from looking personal and unbranded — heavily-designed password emails read as phishing to a wary user, and plainer mail lands in the inbox more reliably.

Whichever you choose, the implementation is the same shape: one shared layout function in packages/core/src/email.ts that takes a title, body blocks and an optional CTA, so all nine templates stop hand-rolling their own markup and any future change happens in one place.

  • Reply to this with a number — or a mix, e.g. "01 for everything, 03 for auth" — and I'll build it.
  • I'll add a plain-text alternative alongside the HTML. Resend accepts both, and sending HTML-only measurably hurts deliverability.
  • Logo will need hosting as a real image at an absolute URL for the header band; the samples above use live text, which is more reliable but less distinctive.
